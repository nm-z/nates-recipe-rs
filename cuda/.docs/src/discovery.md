# CUDA discovery

## Intent and boundary

`cuda/src/discovery.rs` is the single CUDA Driver discovery boundary. It turns
one already loaded `Driver` into one complete, owned `Discovery` snapshot. The
snapshot is a capability observation for the current Driver deployment. It is
not a cache, a device selector, a scheduler input policy, or a benchmark result.
`Driver::discover` performs the same Driver queries again on every call and
returns a fresh value. A caller that needs a current observation must call it
again; no method on `Driver` silently reuses an older snapshot.

The implementation owns only CUDA Driver facts and their validation:

```text
Driver (resolved CUDA Driver API)
  -> Driver::discover()
       -> DriverVersion
       -> DriverCapabilities clone
       -> Vec<DeviceInfo>, one complete record per Driver ordinal
```

The raw `CUdevice` handle remains crate-private inside each `DeviceInfo`. The
native context and runtime modules consume that handle through the same crate,
while `recipe-native-probe` converts the public fields into a backend-neutral
`GpuDescriptor`. Discovery does not open contexts, compile kernels, inspect
Linux sysfs, perform PCI surface hashing, benchmark, choose a GPU, or assign a
Recipe `DeviceId`.

The authoritative implementation is [`cuda/src/discovery.rs`](../../src/discovery.rs#L1-L428).
The raw signatures and constants it invokes are in
[`cuda/src/ffi.rs`](../../src/ffi.rs#L10-L89), and status conversion is in
[`cuda/src/driver.rs`](../../src/driver.rs#L83-L132). The public re-exports are
listed in [`cuda/src/lib.rs`](../../src/lib.rs#L24-L37).

## Data model

The scalar identity values derive `Clone`, `Copy`, `Debug`, equality, ordering,
and hashing where shown by the source. The aggregate records derive `Clone`,
`Debug`, equality, and the traits explicitly listed in their declarations. No
type below performs a new Driver query when it is formatted, compared, or
accessed.

### `DeviceOrdinal`

```text
DeviceOrdinal(i32)
get() -> i32
```

`DeviceOrdinal` is the raw zero-based `CUdevice` enumeration index returned by
`cuDeviceGetCount` and passed to `cuDeviceGet`. Its field and constructor are
private. Discovery constructs it only after the Driver accepts the raw ordinal.
The ordinal is an index within one snapshot, not a stable machine identity.
The public `get` accessor exists for diagnostics and consumers that need to
report the Driver index. Reopening code must not use an ordinal as a fallback
for a missing or changed UUID or descriptor.

### `DeviceUuid`

```text
DeviceUuid([u8; 16])
from_bytes([u8; 16]) -> DeviceUuid
as_bytes(&self) -> &[u8; 16]
```

The value preserves all sixteen bytes returned in `CUuuid`, including an all
zero value. `from_bytes` and `as_bytes` do not validate, normalize, or derive a
replacement. The `Display` representation is exactly:

```text
GPU-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

Every byte is two lowercase hexadecimal digits, grouped as 4, 2, 2, 2, and 6
bytes after the `GPU-` prefix. Equality and ordering compare the original byte
array. Discovery uses the complete value as the duplicate key. The native
probe also places this formatted UUID in the stable CUDA GPU key, together with
the canonical PCI BDF:

```text
cuda:{device.uuid}@{domain:04x}:{bus:02x}:{device:02x}.{function}
```

That string is a probe identity, not a value generated by `recipe-cuda` itself.

### `ComputeCapability`

```text
ComputeCapability {
    major: u32,
    minor: u32,
}
new(major, minor) -> ComputeCapability
```

The values are copied from the `COMPUTE_CAPABILITY_MAJOR` and
`COMPUTE_CAPABILITY_MINOR` Driver attributes without a range check. `Display`
renders `sm_{major}{minor}`, with no separator. `native-probe` later converts
each component to `u8` for `NvidiaTarget`; a component that does not fit is a
probe discovery error. The target architecture and PTX ISA are therefore a
consumer concern, while this module preserves the raw Driver attributes.

### `DriverVersion`

```text
DriverVersion { raw: i32 }
from_raw(raw: i32) -> Result<DriverVersion>
new(major: u32, minor: u32) -> Result<DriverVersion>
raw(self) -> i32
major(self) -> u32
minor(self) -> u32
```

`from_raw` rejects a negative Driver value as
`CudaError::InvalidDriverValue { operation: "cuDriverGetVersion", ... }`.
`new` encodes the CUDA Driver convention as `major * 1000 + minor * 10` using
checked multiplication, addition, and conversion to `i32`. Overflow returns
`InvalidDriverValue` with operation `DriverVersion::new`; no wrapping value is
accepted. The accessors decode `raw / 1000` and `(raw % 1000) / 10`. Thus a raw
value can contain a nonzero units digit, and that digit is preserved by `raw`
but ignored by `major` and `minor`. `Display` is
`{major}.{minor} ({raw})`.

Discovery obtains the raw integer from `cuDriverGetVersion`, validates only its
sign, and stores the original raw value. Driver policy later compares complete
`DriverVersion` values, so callers must not replace the raw value with a
human-readable string.

### `DeviceAttributes`

`DeviceAttributes` is the numeric capability portion of `DeviceInfo`:

| Rust field | Driver attribute | Unit or meaning |
| --- | --- | --- |
| `async_engine_count` | `CU_DEVICE_ATTRIBUTE_ASYNC_ENGINE_COUNT` (`40`) | Number of asynchronous copy engines. |
| `concurrent_kernels` | `CU_DEVICE_ATTRIBUTE_CONCURRENT_KERNELS` (`31`) | Boolean, accepted only as raw `0` or `1`. |
| `warp_size` | `CU_DEVICE_ATTRIBUTE_WARP_SIZE` (`10`) | Device subgroup width. |
| `maximum_threads_per_block` | `CU_DEVICE_ATTRIBUTE_MAX_THREADS_PER_BLOCK` (`1`) | Maximum CUDA workgroup lanes. |
| `maximum_shared_memory_per_block_bytes` | `CU_DEVICE_ATTRIBUTE_MAX_SHARED_MEMORY_PER_BLOCK` (`8`) | Bytes of shared memory per block. |
| `pci_domain_id` | `CU_DEVICE_ATTRIBUTE_PCI_DOMAIN_ID` (`50`) | Numeric PCI domain, compared with the BDF domain by the probe. |
| `pci_bus_id` | `CU_DEVICE_ATTRIBUTE_PCI_BUS_ID` (`33`) | Numeric PCI bus, compared with the BDF bus by the probe. |
| `pci_device_id` | `CU_DEVICE_ATTRIBUTE_PCI_DEVICE_ID` (`34`) | Numeric PCI device, compared with the BDF device by the probe. |
| `core_clock_khz` | `CU_DEVICE_ATTRIBUTE_CLOCK_RATE` (`13`) | Core clock in kHz as reported by the Driver. |
| `memory_clock_khz` | `CU_DEVICE_ATTRIBUTE_MEMORY_CLOCK_RATE` (`36`) | Memory clock in kHz as reported by the Driver. |
| `global_memory_bus_width_bits` | `CU_DEVICE_ATTRIBUTE_GLOBAL_MEMORY_BUS_WIDTH` (`37`) | Global memory bus width in bits. |
| `multiprocessor_count` | `CU_DEVICE_ATTRIBUTE_MULTIPROCESSOR_COUNT` (`16`) | Number of multiprocessors. |

Every raw attribute is first checked through `Driver::check`. A successful
attribute result must fit `u32`; a negative `c_int` becomes
`InvalidDriverValue { operation, detail: "negative attribute value ..." }`.
There is no discovery-side nonzero check for capacities or counts. Consumers
that require a usable queue, workgroup, or memory capability apply their own
policy and report a probe or preparation error.

The PCI attribute fields intentionally do not include a function number. The
textual BDF returned by `cuDeviceGetPCIBusId` carries the function, and the
native probe validates its range separately before using the value as a Linux
sysfs path.

### `DeviceInfo`

```text
DeviceInfo {
    ordinal: DeviceOrdinal,
    uuid: DeviceUuid,
    name: String,
    compute_capability: ComputeCapability,
    pci_bus_id: String,
    total_memory_bytes: u64,
    attributes: DeviceAttributes,
    handle: CuDevice,       # crate-private, raw CUdevice integer
}
```

`name` is the validated, trimmed Driver product name. `pci_bus_id` is the
exact validated string returned by the Driver, including its original case.
`total_memory_bytes` is the `usize` result of `cuDeviceTotalMem_v2`, converted
to `u64`. `handle` is an opaque-to-callers `CuDevice` integer used by
`Context::create`; it is not exposed as an ordinal accessor or serialized
identity. `DeviceInfo` derives equality over all fields, including the raw
handle. `Context` clones the whole record and keeps it beside the raw context,
so runtime diagnostics continue to expose the discovery identity that created
the context.

### `Discovery`

```text
Discovery {
    driver_version: DriverVersion,
    capabilities: DriverCapabilities,
    devices: Vec<DeviceInfo>,
}

device(ordinal: DeviceOrdinal) -> Option<&DeviceInfo>
```

The vector is in ascending raw ordinal order because the loop runs from zero to
the Driver count. `device` is a linear exact equality lookup and returns no
device for an ordinal absent from that snapshot. It does not look up by UUID,
PCI BDF, product name, or a nearest ordinal. `capabilities` is a clone of the
loaded Driver's immutable resolved symbol set. Discovery does not add or remove
capabilities after construction.

## Driver API prerequisites

`Driver::discover` can be called only after `Driver::load` or
`Driver::load_from_path` has successfully resolved every required symbol. The
required discovery symbols are:

```text
cuInit
cuDriverGetVersion
cuDeviceGetCount
cuDeviceGet
cuDeviceGetName
cuDeviceGetUuid
cuDeviceGetPCIBusId
cuDeviceTotalMem_v2
cuDeviceGetAttribute
```

The loader also resolves optional `cuDeviceGetUuid_v2` and stores it as an
`Option`. Optional `cuGetErrorName` and `cuGetErrorString` enrich failures but
are not required for discovery to run. A missing required symbol fails Driver
construction with `MissingRequiredSymbol`; discovery is never entered with a
partially populated API. A failed optional lookup produces `None` and is
visible through `DriverCapabilities`, not through an alternate implementation.

The loaded dynamic library is held by the shared `Arc<DriverInner>` for every
clone of `Driver`. Discovery therefore calls function pointers whose library
handle remains alive for the entire call and for any context or runtime object
that cloned the Driver. Loader errors are outside the per-device validation
steps, but they are a prerequisite failure for this contract.

## `Driver::discover` algorithm

The implementation is intentionally fail-fast. Each `?` below returns before
the next Driver call, and a failure discards the partial vector. There is no
partial `Discovery` result and no best-effort device omission.

```text
discover(driver):
    check("cuInit", api.init(0))

    raw_version := 0
    check("cuDriverGetVersion", api.driver_get_version(&raw_version))
    driver_version := DriverVersion::from_raw(raw_version)

    raw_count := 0
    check("cuDeviceGetCount", api.device_get_count(&raw_count))
    count := usize::try_from(raw_count)
    allocate devices with capacity count
    uuids := BTreeMap<DeviceUuid, c_int>

    for raw_ordinal in 0 .. raw_count:
        device := discover_device(raw_ordinal)
        if uuids.insert(device.uuid, raw_ordinal) replaced first:
            return DuplicateDeviceUuid(first, raw_ordinal)
        append device

    return Discovery {
        driver_version,
        capabilities: driver.capabilities().clone(),
        devices,
    }
```

`raw_count` is a signed `c_int`. A negative count cannot be converted to a
capacity and returns `InvalidDriverValue` for `cuDeviceGetCount`. A count of
zero is valid and produces an empty vector if the caller is using the CUDA
crate directly. The production `ProbeEngine` later rejects an empty complete
GPU inventory because a measured calculation device is required.

The `BTreeMap` is used only for deterministic duplicate detection. It does not
sort or reorder `devices`, and it does not choose a preferred ordinal. On a
duplicate UUID, the first and second raw ordinals are retained in
`CudaError::DuplicateDeviceUuid` and the complete discovery fails.

## Per-device query order and validation

`discover_device(raw_ordinal)` first obtains the raw `CUdevice` handle, then
reads fields in this order. A later field is never observed if an earlier call
or conversion failed.

| Order | Helper and Driver call | Result and validation |
| ---: | --- | --- |
| 1 | `cuDeviceGet(&handle, raw_ordinal)` | Driver status must be success. The handle is retained privately. |
| 2 | `device_name`: `cuDeviceGetName(buffer, 256, handle)` | Buffer must contain a NUL; bytes before NUL must be UTF-8; trimmed name must be nonempty. |
| 3 | `device_uuid`: optional `cuDeviceGetUuid_v2`, then required `cuDeviceGetUuid` when needed | See the UUID fallback contract below. The sixteen returned bytes are preserved. |
| 4 | `device_pci_bus_id`: `cuDeviceGetPCIBusId(buffer, 32, handle)` | Buffer must contain a NUL, UTF-8, and the exact textual grammar `dddd:bb:dd.f`. |
| 5 | `device_memory`: `cuDeviceTotalMem_v2(&usize, handle)` | Status must be success; `usize` must convert to `u64`. |
| 6 | `COMPUTE_CAPABILITY_MAJOR` | Status must be success; signed value must fit `u32`. |
| 7 | `COMPUTE_CAPABILITY_MINOR` | Status must be success; signed value must fit `u32`. |
| 8 | `CONCURRENT_KERNELS` | Status must be success; only `0` maps to `false` and `1` maps to `true`. |
| 9 | `ASYNC_ENGINE_COUNT` | Checked `u32`. |
| 10 | `WARP_SIZE` | Checked `u32`. |
| 11 | `MAX_THREADS_PER_BLOCK` | Checked `u32`. |
| 12 | `MAX_SHARED_MEMORY_PER_BLOCK` | Checked `u32`. |
| 13 | `PCI_DOMAIN_ID` | Checked `u32`. |
| 14 | `PCI_BUS_ID` | Checked `u32`. |
| 15 | `PCI_DEVICE_ID` | Checked `u32`. |
| 16 | `CLOCK_RATE` | Checked `u32`. |
| 17 | `MEMORY_CLOCK_RATE` | Checked `u32`. |
| 18 | `GLOBAL_MEMORY_BUS_WIDTH` | Checked `u32`. |
| 19 | `MULTIPROCESSOR_COUNT` | Checked `u32`. |

After order 19, the helper builds `DeviceInfo` with
`DeviceOrdinal(raw_ordinal)` and `ComputeCapability::new(major, minor)`. There
is no hidden query for a device's PCI function, serial number, board name,
memory type, stream count, or UUID text.

### Driver status conversion

Every Driver call in the sequence uses `Driver::check`. A zero status returns
`Ok(())`. Any other status returns `CudaError::DriverCall(DriverCallError)`
containing the static operation label and the exact numeric `DriverStatus`.
When the optional error symbols are available, `check` also asks
`cuGetErrorName` and `cuGetErrorString` for diagnostic text. If those lookups
are absent or themselves fail, the numeric status remains authoritative. The
discovery code does not retry a failed call, replace it with a Runtime API call,
or continue with a default field.

### Name buffer contract

`device_name` allocates `[c_char; 256]` and passes its length as a checked
`c_int`. It finds the first zero byte. No zero within the capacity is an error
(`InvalidDeviceName { ordinal, detail: "not NUL-terminated within 256 bytes" }`).
The bytes before that zero must be UTF-8. The resulting Rust string is trimmed
with `str::trim`; an empty result fails as `InvalidDeviceName`. Interior bytes
after the first NUL are ignored because the Driver C string ends at the first
NUL. The original untrimmed spelling is not retained.

### UUID selection and fallback

`device_uuid` initializes a zeroed `CuUuid`, then applies this exact decision:

```text
if api.device_get_uuid_v2 exists:
    status := cuDeviceGetUuid_v2(&uuid, handle)
    if status == CUDA_SUCCESS:
        return DeviceUuid(uuid.bytes)
    if status != CUDA_ERROR_NOT_SUPPORTED:
        return check("cuDeviceGetUuid_v2", status)

status := cuDeviceGetUuid(&uuid, handle)
check("cuDeviceGetUuid", status)
return DeviceUuid(uuid.bytes)
```

`CUDA_ERROR_NOT_SUPPORTED` (`801`) from v2 is the one intentional fallback.
The v1 symbol is required at Driver load time, so the fallback is always
available when discovery starts. A v2 status other than success or not
supported is a real Driver failure and is not downgraded. A missing v2 symbol
also follows the v1 path. No UUID validity predicate is applied after success;
duplicate detection is the only snapshot-level UUID rule.

### PCI bus ID grammar

`device_pci_bus_id` allocates `[c_char; 32]`, passes a checked `c_int` length,
finds the first NUL, decodes the bytes as UTF-8, and calls
`validate_pci_bus_id`. The accepted grammar is exactly:

```text
dddd:bb:dd.f
```

where `dddd`, `bb`, and the second `dd` have lengths 4, 2, and 2 and every
character is an ASCII hexadecimal digit. The function component has length one
and must be an ASCII decimal digit. The helper uses `split_once` for the two
colons and the dot, so missing or extra separators fail. It does not parse or
normalize case, and it does not check numeric ranges beyond the fixed widths.
Consequently, the direct CUDA boundary accepts a textual function digit `8` or
`9`; the native probe applies the Linux BDF range `0..=7` before sysfs access.

Missing NUL, invalid UTF-8, or a grammar error returns
`InvalidDriverValue` with operation `cuDeviceGetPCIBusId`. The detail includes
the raw ordinal for terminator or UTF-8 failures, and includes the returned
string and grammar detail for validation failures. The exact original string is
stored in `DeviceInfo` after validation.

### Numeric conversions

`device_memory` reads into a `usize` because that is the FFI signature and
converts with `u64::try_from`. `device_attribute` reads into a signed `c_int`
and converts with `u32::try_from`. A negative value is an invalid Driver value;
there is no saturating conversion. The conversion operation label is the exact
caller-supplied string, for example
`cuDeviceGetAttribute(COMPUTE_CAPABILITY_MAJOR)`. The Boolean
`CONCURRENT_KERNELS` check occurs after the signed-to-`u32` conversion, so a
negative raw value fails as an invalid numeric attribute and a nonzero value
other than `1` fails as an invalid Boolean attribute.

## Identity rules

The three identity forms have deliberately different scopes:

| Identity | Scope | Accepted use | Forbidden substitution |
| --- | --- | --- | --- |
| `DeviceOrdinal` | One current Driver enumeration | Index into the same `Discovery`, diagnostics, `cuDeviceGet` input during that call | Stable profile key or reopening fallback. |
| `DeviceUuid` | CUDA device identity across ordinal re-enumeration | Duplicate detection, `DeploymentIdentity`, native executor context check, probe key | A generated UUID, product-name surrogate, or PCI-only replacement. |
| `pci_bus_id` | Driver-reported PCI function text | Numeric consistency check, canonical sysfs BDF lookup in native probe | Raw filesystem path without grammar and range validation. |

The UUID and BDF are combined by the native probe because either alone is
insufficient for all downstream purposes. UUID identifies the CUDA device; BDF
anchors the device to Linux PCI surface and link data. The Driver layer does
not claim that its textual PCI value and numeric PCI attributes agree. That
cross-source invariant belongs to `CudaBackend::descriptor`.

`DeploymentIdentity::from_discovery` in
[`cuda/src/artifact.rs`](../../src/artifact.rs#L31-L55) is the only constructor
that turns this snapshot into a deployment identity. It returns `None` unless
the supplied `DeviceInfo` has both an equal ordinal and an equal UUID among the
snapshot's devices. On success it copies the snapshot `driver_version` and
`capabilities`, and the device UUID and `compute_capability`. It does not copy
the product name, PCI BDF, memory, or numeric attributes. This is an
existence-and-membership check, not a fresh discovery call.

## Native probe consumption

The production CUDA consumer is
[`native-probe/src/cuda.rs`](../../../native-probe/src/cuda.rs#L75-L590).
`recipe-cuda` supplies the raw snapshot; the native probe adds hardware
presence policy, library provenance, PCI sysfs identity, target validation, and
benchmark lifecycle.

### Opening a backend

`CudaBackend::open` follows this exact path:

```text
PCI sysfs root and vendor 0x10de
  -> no NVIDIA accelerator: Ok(None)
  -> accelerator present:
       selected_library(config.cuda.library, "CUDA Driver")
       -> canonical existing library path and digest
       -> Driver::load_from_path(path UTF-8)
       -> Driver::discover()
       -> Some((PinnedLibrary, Driver, Discovery))
```

The preflight is implemented by
[`native-probe/src/identity.rs`](../../../native-probe/src/identity.rs#L169-L204).
If no matching NVIDIA accelerator is present, a missing CUDA library is
allowed and the backend contributes no devices. Once PCI presence is detected,
missing configured library candidates, invalid candidate paths, a non-UTF-8
path, Driver loading failure, or any exhaustive discovery failure is fatal as a
`ProbeError::Discovery`. There is no downgrade from a present but broken
backend to absence.

`selected_library` is outside the CUDA crate. It requires absolute candidate
paths, accepts only regular files or symlinks, canonicalizes the first existing
candidate, hashes its bytes, and deduplicates canonical targets. The CUDA crate
receives one already selected UTF-8 path and does not search candidates itself.

### Descriptor construction

`CudaBackend::descriptor` consumes a `PinnedLibrary`, a `Discovery`, and one
`DeviceInfo`:

1. Parse `device.pci_bus_id` with the probe grammar. The probe parser accepts
   hexadecimal domain, bus, and device fields, parses the function as decimal,
   and rejects a function above `7`.
2. Compare the parsed numeric domain, bus, and device to
   `device.attributes.pci_domain_id`, `pci_bus_id`, and `pci_device_id`.
   Any disagreement is a discovery error. The function has no Driver numeric
   attribute and therefore cannot be compared at this step.
3. Render a lowercase canonical sysfs BDF with widths `04x:02x:02x.f` and
   obtain the PCI driver, firmware, and link surfaces from `pci_surface`.
   Uppercase Driver hex is accepted by parsing but never used as the sysfs
   spelling.
4. Convert compute capability major and minor to `u8`, construct an
   `NvidiaTarget` with configured `ptx_isa`, and validate that target. A value
   that does not fit or fails target validation is a discovery error.
5. Build the stable key `cuda:{uuid}@{sysfs_bdf}` and the backend-neutral
   `GpuDescriptor`.

The descriptor retains these discovery facts and policies:

| Descriptor field | Source |
| --- | --- |
| `key` | Formatted UUID plus canonical PCI BDF. |
| `name` | Validated, trimmed `DeviceInfo::name`. |
| `capacity_hint` | `DeviceInfo::total_memory_bytes`. |
| `target.architecture` | `ComputeCapability` rendered as the NVIDIA target architecture. |
| `driver` | Raw `Discovery::driver_version` plus hashed PCI driver surface. |
| `runtime_abi` | Raw Driver version plus selected library identity. |
| `firmware` | Hashed PCI firmware surface. |
| `link_identity` | Hashed PCIe link surface. |
| `subgroup_lanes` | `attributes.warp_size`. |
| `maximum_workgroup_lanes` | `attributes.maximum_threads_per_block`. |
| `maximum_shared_memory_per_workgroup` | `attributes.maximum_shared_memory_per_block_bytes`. |
| `transfer_overlaps_calculation` | `async_engine_count != 0 && concurrent_kernels`. |

The descriptor deliberately reports PCIe, full duplex, one host-to-device lane,
one device-to-host lane, asynchronous submission, one concurrent task, and the
bounded `CUDA_MAXIMUM_SUBMISSION_QUEUES` ceiling from
`recipe-native-executor`. These are consumer policies, not additional fields in
`DeviceInfo`.

### Exact matching for benchmarks

`matching_device` re-runs `descriptor` for every device in the newly opened
snapshot and compares the complete `GpuDescriptor` to the expected measured
descriptor. More than one equal descriptor is a benchmark error. No match is a
benchmark error saying the GPU disappeared or changed identity. Ordinal,
product name, capacity, UUID alone, and nearest target are not fallback keys.

`benchmark_open` calls `open`, then exact matching, and clones the selected
`DeviceInfo`. `benchmark_device` creates a context from that record and uses
the discovered total memory and numeric attributes to bound real transfer and
kernel work. A device that changes between descriptor creation and benchmark
opening is rejected before native benchmark operations begin.

The benchmark then creates a `SchedulingPolicy::Yield` context and one
nonblocking stream, allocates bounded pinned-host and device buffers, verifies
host-to-device, device-to-host, and device-to-device copies, builds and loads a
Recipe-owned cubin for the discovered SM target, launches the inspected FMA
entry, downloads the result, and verifies the output. Event-backed submissions
are polled to terminal completion. A deadline does not cancel CUDA work, since
the Driver exposes no cancellation primitive; a timed-out operation keeps its
same pending token and is polled by the capped cleanup cadence before the
benchmark returns its timeout error.

### Complete native inventory

[`native-probe/src/native.rs`](../../../native-probe/src/native.rs#L245-L299)
calls every configured backend's `discover`, sorts all descriptors by key, and
rejects duplicate keys emitted by different backends. The normal constructor
marks the inventory `exhaustive = true`; CUDA-only and HSA-only diagnostic
constructors deliberately mark it false. `ProbeEngine::inspect` rejects a
non-exhaustive inventory and an empty inventory before profile construction.
Thus one successful measured profile means all required backend surfaces were
enumerated, not merely that one CUDA call succeeded.

For a benchmark, `NativeGpuProbe::benchmark_gpu` rediscoveries each backend and
requires exactly one backend to emit a descriptor equal to the measured input.
If two backends claim the same complete descriptor, it returns a benchmark
error; if none claims it, it reports that the GPU identity changed. This owner
check is separate from the CUDA-only `matching_device` loop and does not use a
backend or ordinal guess.

## Exact reopening and context ownership

[`native-probe/src/bindings.rs`](../../../native-probe/src/bindings.rs#L120-L317)
reopens current native bindings for preparation and execution. The sequence is:

```text
with_native_execution_bindings
  -> probe.discover_all()
  -> profile.resolve_local_inventory(host, inventory)
  -> partition expected GPU origins by exact descriptor backend and key
  -> CudaBackend::open()                 # fresh Driver and Discovery
  -> descriptor every reopened DeviceInfo
  -> require every reopened descriptor key in measured expected set
  -> DeploymentIdentity::from_discovery(&discovery, device)
  -> Context::create(&driver, device, ContextFlags::default())
  -> lend Context through CudaBinding callback
```

`realize_cuda` rejects an unexpected reopened key, a duplicate expected key, a
missing expected key, a missing Driver surface, or a missing deployment
membership result. It sorts realized bindings by Recipe `DeviceId` only after
all identity checks pass. The callback lifetime borrows the `Context`; the raw
Driver context cannot escape this preparation/execution scope.

Before that backend-specific work, `profile.resolve_local_inventory` requires
the current host fingerprint and the complete current RAM, storage, and GPU key
sets to equal the measured profile. It does not resolve a CUDA device by
ordinal, product name, capacity, or performance similarity.

`Context::create` uses `DeviceInfo::handle` to call `cuCtxCreate_v2`, rejects a
null context returned with success, pops the just-created context, and verifies
the exact handle returned by `cuCtxPopCurrent_v2`. It stores a clone of
`DeviceInfo`, including UUID, compute capability, attributes, and raw handle.
The CUDA discovery module does not revalidate a handle against a different
`Driver`; callers must pass the record from the exact reopened snapshot.

`native-executor/src/cuda.rs` validates the resulting binding before resource
realization: the context's discovered UUID must equal
`DeploymentIdentity::device_uuid`, and its compute capability must equal
`DeploymentIdentity::target` ([`validate_binding`](../../../native-executor/src/cuda.rs#L1633-L1646)).
The same binding carries the snapshot's Driver capabilities and version into
artifact compatibility checks. A mismatch is an executor error, not a second
discovery or a replacement context.

## Preparation and artifact consumers

`src/native_prepare.rs::cuda_spec` converts `DeploymentIdentity::target` into
the configured NVIDIA target and requires the measured descriptor backend,
architecture, and ABI to agree. It also requires every
`REQUIRED_DRIVER_SYMBOLS` entry to be present in the snapshot capabilities. The
Driver version is placed into the CUDA artifact policy as both the measured
minimum and current maximum for the realized run. This policy is assembled in
[`prepare/src/production.rs`](../../../prepare/src/production.rs#L177-L190)
and becomes `recipe_cuda::ArtifactIdentity` when the cubin image is built
([`runtime_kind`](../../../prepare/src/production.rs#L577-L607)).

`DeploymentIdentity` intentionally has less data than `DeviceInfo`: artifact
compatibility is target, Driver version, required-symbol, toolchain, and cubin
identity validation. UUID membership is enforced while reopening and by the
executor binding check; the artifact validator does not invent a UUID check for
the cubin itself.

The root facade exposes the module as `recipe::engine::cuda`, but that is a
re-export only. No second discovery implementation exists. Direct workspace
consumers are `recipe-native-probe`, `recipe-prepare` through its native
preparation adapter, and `recipe-native-executor`; the facade is a presentation
edge. Other planning and scheduling crates consume the backend-neutral measured
profile and `DeviceId`, not raw CUDA ordinals or handles.

## Failure contract

The following table is the complete discovery-specific failure surface. A
non-discovery Driver or loader failure can occur before this module is entered,
but no row below is swallowed or converted to a default.

| Observed condition | Error and consequence |
| --- | --- |
| `cuInit`, version, count, device, name, UUID, PCI, memory, or attribute call returns a non-success status | `CudaError::DriverCall` with exact operation and numeric status, plus optional Driver text; the whole discovery call fails. |
| `cuDriverGetVersion` returns a negative value | `InvalidDriverValue` for `cuDriverGetVersion`; no snapshot. |
| `cuDeviceGetCount` returns a negative count | `InvalidDriverValue` for `cuDeviceGetCount`; no allocation or enumeration. |
| Device name has no NUL within 256 bytes | `InvalidDeviceName { ordinal, ... }`. |
| Device name bytes before NUL are not UTF-8 | `InvalidDeviceName { ordinal, ... }`. |
| Trimmed device name is empty | `InvalidDeviceName { ordinal, detail: "empty name" }`. |
| PCI text has no NUL within 32 bytes | `InvalidDriverValue` for `cuDeviceGetPCIBusId`. |
| PCI text is not UTF-8 | `InvalidDriverValue` for `cuDeviceGetPCIBusId`. |
| PCI text does not match `dddd:bb:dd.f` | `InvalidDriverValue` for `cuDeviceGetPCIBusId`. |
| Optional UUID v2 returns `CUDA_ERROR_NOT_SUPPORTED` | Fall back once to required `cuDeviceGetUuid`; this status is not an error. |
| Optional UUID v2 returns another non-success status | `DriverCall` for `cuDeviceGetUuid_v2`; no v1 fallback. |
| Required UUID v1 fails | `DriverCall` for `cuDeviceGetUuid`; no UUID default. |
| `CONCURRENT_KERNELS` is not `0` or `1` after numeric conversion | `InvalidDriverValue` for the Boolean attribute. |
| Any signed numeric attribute is negative | `InvalidDriverValue` for that attribute operation. |
| Total memory does not fit `u64` | `InvalidDriverValue` for `cuDeviceTotalMem_v2`. |
| Two ordinals return equal `DeviceUuid` values | `DuplicateDeviceUuid { first_ordinal, second_ordinal }`; no ambiguous snapshot. |
| Optional Driver error-name/string query is absent or fails | The original numeric `DriverCall` remains; diagnostic text is `None`. |

The error type is [`CudaError`](../../src/error.rs#L33-L130). PCI parsing does
not have a dedicated enum variant, so callers must retain the operation label
and detail when presenting the failure. `native-probe` prefixes all errors
from `Driver::load_from_path` and `Driver::discover` with
`ProbeError::Discovery("load CUDA Driver: ...")` or
`ProbeError::Discovery("exhaustive CUDA discovery: ...")`. It does not convert
a malformed or incomplete snapshot into an empty inventory.

Consumer failures are intentionally distinct from Driver discovery failures:

| Layer | Identity or discovery failure |
| --- | --- |
| Native probe open | Present NVIDIA PCI hardware with no selected library, invalid library/path, load error, or exhaustive discovery error becomes `ProbeError::Discovery`. |
| Native probe descriptor | Invalid function range, PCI numeric disagreement, missing sysfs surface, target conversion/validation failure, or invalid labels becomes `ProbeError::Discovery`. |
| Native probe exact match | Duplicate descriptor is a benchmark error; no descriptor is a benchmark identity-change error. |
| Native probe inventory | Duplicate backend key, incomplete diagnostic inventory, or no GPU fails profile construction. |
| Binding reopen | Unexpected, duplicate, missing, or backend-less measured key fails preparation-scoped binding construction. |
| Deployment identity | A `DeviceInfo` outside the reopened snapshot returns `None`; the binding path turns that into a discovery error. |
| Native executor | Context UUID or compute capability mismatch becomes an artifact mismatch; missing required Driver capability is a preparation identity error. |

No failure path retries a Driver call, substitutes a Runtime API, chooses a
different ordinal, accepts a product-name match, or invents a synthetic
capacity. The observed failure remains visible at the layer that detected it.

## Invariants

These statements are the parseable contract for code review and consumer
implementations:

```text
discovery.calls_are_fresh             = true
discovery.enumeration_is_exhaustive  = true for a successful Driver::discover
discovery.devices_order               = ascending raw ordinal
discovery.device_lookup               = exact DeviceOrdinal within one snapshot
discovery.partial_result               = forbidden
discovery.uuid_width                  = 16 bytes
discovery.uuid_duplicate_policy       = fail whole snapshot
discovery.uuid_v2_fallback             = only CUDA_ERROR_NOT_SUPPORTED
discovery.name_capacity_bytes          = 256 including NUL capacity
discovery.pci_capacity_bytes           = 32 including NUL capacity
discovery.pci_grammar                  = dddd:bb:dd.f
discovery.pci_case                     = preserve Driver text, consumer canonicalizes sysfs spelling
discovery.pci_function_range           = lexical ASCII digit here, 0..=7 in Linux probe consumer
discovery.concurrent_kernels_values   = {0, 1}
discovery.numeric_attribute_domain     = nonnegative c_int fitting u32
discovery.total_memory_domain          = usize fitting u64
discovery.ordinal_is_stable_identity   = false
discovery.uuid_is_stable_cuda_identity = true
discovery.handle_is_public             = false
discovery.sysfs_is_read                = false
discovery.benchmark_is_run             = false
discovery.context_is_created          = false
```

The successful snapshot is immutable by convention and by field ownership:
`Discovery` owns its `Vec<DeviceInfo>`, each `DeviceInfo` owns its `String`, and
the Driver capability set is cloned from an immutable `BTreeSet`. Cloning a
snapshot copies facts; it does not refresh them. Any consumer that needs to
prove current hardware identity must open and discover again, then compare the
complete backend descriptor or exact deployment fields as its contract states.

benchmark consumers. A compile pass or an emitted `Discovery` debug value is
not evidence that the live Driver, PCI surface, or device identity is valid.
