Recurrent-family implementation specs (2026-07-17, workflow wf_c91aed81)

==== SPEC 1: shortconv recurrent (gated short convolution)
ARCHS: lfm2, lfm2moe. Both hybrid: attention layers interleaved with gated-shortconv layers. Fixtures measured: datasets/llamacpp-archs-seed42/lfm2-dense.gguf (arch=lfm2, block_count=2, embedding_length=256, ff=384, shortconv.l_cache=3, leading_dense_block_count=2 so all-dense FFN) and lfm2moe-moe.gguf (arch=lfm2moe, block_count=2, leading_dense_block_count=1, expert_count=2, expert_used_count=1, expert_feed_forward_length=384, expert_gating_func=2 [sigmoid], shortconv.l_cache=3). Reference builders: llama.cpp/src/models/lfm2.cpp (full graph + shortconv block at :157-226), lfm2moe.cpp:1-85 (reuses lfm2::graph via models.h:1831 `using graph = llama_model_lfm2::graph<iswa>`). Depthwise-conv op ggml_ssm_conv defined llama.cpp/ggml/src/ggml.c:5548, CPU math llama.cpp/ggml/src/ggml-cpu/ops.cpp:9557-9605.
MATH:
Per shortconv layer, input h is [t, ne] token-major (ne=n_embd, feature-contiguous in OUR arena, cf. gpu_gemm_bt_f64 convention common.rs:571). Steps (llama.cpp lfm2.cpp:170-225):
(1) operator_norm: x = RMSNorm(h, gamma=attn_norm[l]) over ne. Existing gpu_rmsnorm_f64.
(2) in_proj GEMM: BCx = x @ in_proj^T, in_proj is [3*ne, ne] (gguf ne=[ne,3ne]), out [t, 3ne]. The 3ne output splits into B=cols[0,ne), C=cols[ne,2ne), Xg=cols[2ne,3ne) (ggml chunk order b,c,x at lfm2.cpp:180-185). CLEANEST: split in_proj weight into three contiguous [ne,ne] row-blocks wB/wC/wX at load (rows [0,ne)/[ne,2ne)/[2ne,3ne) are contiguous, exactly like synth_ffn_slices llm.rs:1234) and issue 3 GEMMs producing B,C,Xg each [t,ne]. Same FLOPs as one fused GEMM, avoids strided views.
(3) pre-conv gate: bx = B (elementwise-mul) Xg, [t,ne]. Existing gpu_mul (kernels.rs:2688).
(4) causal depthwise conv: conv_out[p,f] = sum_{k=0..L-1} conv_w[f,k] * bx[p-(L-1)+k, f], with bx[j,f]=0 for j<0 (left zero-pad of L-1; the from-scratch conv state is zeros because our decode does one full-batch pass, logits_last llm.rs:110-135, no cross-call recurrent cache; n_embd_r state = ne*(L-1) per llama-hparams.cpp:189 is only needed for streamed KV which we do not use). L = shortconv.l_cache = 3. conv_w is [ne, L] (gguf [L,ne] reversed). This is exactly ggml_ssm_conv with a zeroed state prefix (ops.cpp:9595 sumf += s[i0+i1*ncs]*c[i0+i1*nc]).
(5) post-conv gate: y = C (elementwise-mul) conv_out, [t,ne]. Existing gpu_mul.
(6) out_proj GEMM: sc = y @ out_proj^T, out_proj [ne,ne], out [t,ne]. Existing gpu_gemm_bt_f64.
(7) residual: h_mid = h + sc (lfm2.cpp:259, note residual is on the RAW block input, prev_cur, not the normed x). Existing gpu_add_into.
(8) FFN: ffn_norm(h_mid) then SwiGLU dense (dense layers) or sigmoid-gated MoE (lfm2moe moe layers); h_out = h_mid + ffn_out (lfm2.cpp:261-268). Existing ffn() / layer_moe().
Note the ColBert-embedding variant (hparams.causal_attn==false, lfm2.cpp:197-201) uses a centered symmetric pad instead of causal prefix; not present in the decoder fixtures, out of scope for these gguf.
KERNELS NEEDED:
ONE new small kernel: shortconv_causal_dwconv(bx, conv_w, out, t, ne, L). Math (f64, exactly ggml_ssm_conv with zero state prefix): out[p*ne + f] = sum_{k=0..L-1} ( (p-(L-1)+k >= 0) ? conv_w[f*L + k] * bx[(p-(L-1)+k)*ne + f] : 0 ). Layout: bx and out are [t,ne] token-major feature-contiguous (our arena convention); conv_w is [ne,L] row-major (channel-major, tap-contiguous, matching the reversed gguf [L,ne] tensor). Launch geometry: one thread per output element, total = t*ne, block=dim3(256), grid=dim3((t*ne+255)/256); thread idx -> f=idx%ne, p=idx/ne; inner serial loop of L=3 multiply-adds; implicit left zero-pad by the j>=0 guard (no padded buffer, no allocation). Register/LDS: trivial (L small); reads bx once per tap, conv_w[f,*] L contiguous. This is the only genuinely new primitive; add a Rust wrapper gpu_shortconv_dwconv beside gpu_conv1d_into (kernels.rs:7233). Optional load-time helper (no kernel): tri-split of in_proj [3ne,ne] into wB/wC/wX contiguous row-blocks, modeled on synth_ffn_slices (llm.rs:1234).
KERNELS EXISTING:
All reusable from our tree: gpu_gemm_bt_f64 (gpu-core/src/infer_ops.rs:331) for in_proj/out_proj/attn projections; gpu_mul (gpu-core/src/kernels.rs:2688) for the two elementwise gates B*x and C*conv_out; gpu_rmsnorm_f64 (infer_ops.rs:141) for operator_norm/ffn_norm; gpu_add_into (kernels.rs:2564) for residuals; ffn()/layer_moe() (common.rs:419,482) for the FFN branch; attn_block (common.rs:252) already covers the attention layers (qk_norm via q_norm[128]/k_norm[128], rope via gpu_rope_partial, GQA via gpu_gqa_attn); gpu_bias_add (kernels.rs:4864) for the qkv bias once mapped. The existing depthwise-conv primitive convx_dwconv1d (gpu-core/src/kernels/convx.hip:209-236, math y[co,t]=bias+sum_k x[co,t+k]*w[co,k]) computes the SAME conv math but expects x as [N,Cin,L] with time contiguous per channel; our arena is [t,ne] feature-contiguous, so using it would need gpu_transpose (kernels.rs:5437) in+out plus a materialized left-padded buffer (an allocation), which violates the no-alloc-in-loop arena rule. gpu_scan_linear_recurrence (reductions.rs:769, state=a*state+b) is NOT used by shortconv (shortconv is a finite FIR conv, not an IIR scan; that primitive is for the mamba/rwkv diagonal-decay families).
TENSORS:
Measured gguf tensor names/shapes (od of fixtures). Shortconv layer (lfm2 blk.1, lfm2moe blk.1):

  blk.{l}.shortconv.in_proj.weight ne=[256,768] (=[ne, 3*ne])
  blk.{l}.shortconv.out_proj.weight ne=[256,256](=[ne, ne])
  blk.{l}.attn_norm.weight [256]  (operator_norm; reuses attn_norm name, maps to input_layernorm)
  blk.{l}.ffn_norm.weight [256] + ffn_gate/up/down (dense) OR ffn_gate_exps/up_exps/down_exps [256,384,2]+ffn_gate_inp[256,2]+exp_probs_b.bias[2] (lfm2moe moe layer).
Attention layer (blk.0): attn_q/k/v.weight [256,256] + attn_q/k/v.BIAS [256] + attn_q_norm.weight[128] + attn_k_norm.weight[128] + attn_output.weight[256,256] + attn_norm.weight[256].
Globals: token_embd.weight[256,128], token_embd_norm.weight[256], output.weight[256,128].

HYBRID LAYOUT:
Per-layer routing metadata: is_recurrent[l] = (attention.head_count_kv[l] == 0). This is the single interleave signal (lfm2.cpp:10 and lfm2moe.cpp:13 `hparams.is_recr_impl[il] = hparams.n_head_kv(il) == 0`). Measured head_count_kv arrays: lfm2=[2,0], lfm2moe=[2,0] (both fixtures), i.e. layer0=attention, layer1=shortconv. Our dims[l].nkv already holds this per-layer value (llm.rs:497, populated from the head_count_kv array), so is_recr[l] = (dims[l].nkv==0) needs no new parse. GAP: current dispatch (models/mod.rs:293-317) selects ONE Comp per arch by string; lfm2/lfm2moe are Comp::Recurrent (mod.rs:92-93) which routes EVERY layer to layer_recurrent (a q/k/v-scan driver, wrong tensors). Required change: make dispatch route per-layer: if dims[l].nkv==0 run the new shortconv block, else run the attention block (attn_block common.rs:252, which already does qk-norm+rope+GQA). Cleanest is a new Comp::Hybrid variant (or a per-layer branch inside a shortconv driver) that picks shortconv-vs-attn on nkv, and picks dense-vs-moe FFN on layer_is_moe(l) (already works: lfm2moe layer1 has experts.gate_proj so layer_is_moe returns true). FFN interleave (dense vs MoE) is governed by leading_dense_block_count: layers [0,n_dense_lead) dense, rest MoE (lfm2.cpp:47), which coincides with tensor presence.
RISK:
1) token_embd_norm MISMAPPING (highest risk): lfm2 ships the FINAL pre-lm_head norm under tensor name token_embd_norm (LLM_TENSOR_OUTPUT_NORM_LFM2, llama-arch.cpp:375 comment 'fix for wrong tensor name'; applied as output_norm at lfm2.cpp:37,274). Our GLOBAL_MAP (llm.rs:1111) maps token_embd_norm.weight -> embed_norm.weight, which the decode path applies right AFTER embedding (llm.rs:127-130), not before lm_head; and decoder_norm loads from output_norm.weight (llm.rs:1447) which lfm2 does NOT ship, so the final norm would be missing/default. Fix: for lfm2/lfm2moe, token_embd_norm.weight must resolve to the decoder norm (norm.weight), not embed_norm. Needs arch-aware mapping (the same gguf name means different things across arches). 2) Per-layer hybrid dispatch does not exist yet (see hybrid_layout) -- the biggest structural change. 3) qkv bias unmapped+unapplied (lfm2 attention has it). 4) lfm2 attention layers are SWA (sliding_window=16); our gqa uses a full causal mask (prefix=t, common.rs:314) -- needs the sliding mask for exact parity on long sequences (negligible at t<=16). 5) lfm2moe expert_gating_func=2 is sigmoid; layer_moe currently softmaxes (common.rs:508). 6) Fixture weights are F32 (4-byte), but load_model_gguf hardcodes nbytes=elems*2 (bf16 assumption, llm.rs:1225); verify the dequant path handles F32 gguf or the whole family mis-reads offsets (affects every recurrent fixture, not just shortconv).

==== SPEC 2: talkie (non-param-RMS + embd-skip residual + asymmetric qk-norm), stage-6 skipped
ARCHS: talkie (dense attention, no recurrence, no shortconv despite shortconv.l_cache=0 in KV). Fixture: datasets/llamacpp-archs-seed42/talkie-dense.gguf (block_count=2, embedding_length=256, ff=384, head_count=2, head_count_kv=2 [scalars, all-attention], logit_scale=1.0, layer_norm_rms_epsilon=1e-5, key_length=value_length=128, rope.dimension_count=128). Reference: llama.cpp/src/models/talkie.cpp:1-149 (full graph), hparams talkie.cpp:3-11 reads LLM_KV_ATTENTION_LAYERNORM_RMS_EPS + LLM_KV_LOGIT_SCALE. Currently mis-specced in our TABLE as `('talkie', Comp::Dense(Spec::dense(Ffn::SiluGate).qk()))` (mod.rs:157) which demands parametric input/ffn norms and a k-norm gain that the model does NOT ship, so it loads wrong.
MATH:
Per layer (talkie.cpp:64-132), h=[t,ne]:
(1) embd_skip is set ONCE before the loop: emb = tok_embd[tokens]; inpL = RMSNorm_noparam(emb); embd_skip = inpL (talkie.cpp:49-53). All norms non-parametric.
(2) x = RMSNorm_noparam(inpL) (talkie.cpp:68, gamma=nullptr).
(3) attention: Q=x@wq^T+bq, K=x@wk^T+bk, V=x@wv^T+bv (qkv bias present). rope(Q,Q) and rope(K) FIRST (talkie.cpp:76-84). THEN per-head norm AFTER rope: Q = RMSNorm(Q, q_norm) where q_norm is a per-HEAD scalar gain [1,n_head] broadcast over head_dim (talkie.cpp:87); K = RMSNorm_noparam(K) (talkie.cpp:90, NO k gain -- 'no k gain' comment talkie.cpp:25). GQA attn with scale 1/sqrt(head_dim), then out_proj wo (talkie.cpp:95-98). cur = attn_out.
(4) ffn_inp = cur + inpSA where inpSA = inpL (raw layer input, talkie.cpp:65,107).
(5) x2 = RMSNorm_noparam(ffn_inp); ffn = SwiGLU(SiLU) dense; cur = ffn + ffn_inp (talkie.cpp:110-121).
(6) EMBD-SKIP RESIDUAL: skip = embd_skip * out_scale[l] (per-layer scalar tensor); cur = cur + skip (talkie.cpp:123-126). embd_skip is the SAME normed embedding for every layer.
(7) inpL = cur; next layer.
Final: cur = RMSNorm_noparam(inpL); logits = cur @ output^T; logits = logits * logit_scale (talkie.cpp:137-143). No final softcap. Distinctives vs a standard block: (a) EVERY block/final/embed norm is non-parametric RMS (only q_norm carries a weight); (b) q gain is a per-head scalar applied post-rope, k is non-param post-rope (asymmetric); (c) an out_scale-scaled copy of the initial normed embedding is added to every layer output.
KERNELS NEEDED:
No new HIP kernel strictly required IF gpu_broadcast_mul can express 'multiply each head-block by its scalar gain' (Q reshaped [t, n_head, head_dim], gain[n_head] broadcast over head_dim and over tokens). If that broadcast pattern is not directly expressible by an existing launcher, add a trivial per-head-scale kernel: qhead_scale(q, gain, out, rows=t*n_head, hd, n_head) with out[r*hd+d] = q[r*hd+d] * gain[(r % n_head)] -- one thread per element, block 256, grid ceil(t*n_head*hd/256). The real work is driver-level, not kernel-level: talkie needs a dedicated composition (either a new Spec with flags {nonparam-block-norms already exists as sp.nonparam common.rs:64, qk_norm_post_rope, head_scalar_q_gain, nonparam_k_norm, embd_skip_scale, nonparam_final_norm+nonparam_embed_norm} or a small dedicated layer_talkie driver). The existing attn_block applies qk_norm BEFORE rope and expects a head_dim-length gamma for both q and k (common.rs:335-345), so it cannot express talkie's post-rope, per-head-scalar-q, non-param-k pattern without new flags.
KERNELS EXISTING:
gpu_rmsnorm_f64_nogamma (gpu-core/src/infer_ops.rs:167, non-param RMS) for input/attn/ffn/final norms and for K post-rope; apply_norm (common.rs:206) already routes NormK::Rms with gamma=None to it. gpu_gemm_bt_f64 for q/k/v/o/ffn/lm_head; gpu_bias_add (kernels.rs:4864) for qkv bias; gpu_rope_partial for rope; gpu_gqa_attn for attention; gpu_glu_silu (infer_ops.rs:309) + gpu_gemm for SwiGLU; gpu_add_into for residuals; gpu_scale_f64_inplace (infer_ops.rs:357) with Model.ls_dev[l] (the per-layer scalar buffer already built from layer_scalar, llm.rs:1438) for the out_scale multiply; models::logit_scale path (llm.rs:139-143) for the final logit scale. The per-head-scalar q gain can reuse gpu_broadcast_mul (kernels.rs:5587, multiplies matrix columns by a per-column vector) after a plain gpu_rmsnorm_f64_nogamma over head_dim: view Q as [t*n_head, head_dim], rms-norm rows, then multiply each row's head by q_norm[head] via a length-n_head broadcast.
TENSORS:
Measured (talkie-dense.gguf, both blk.0/blk.1 identical shape set):
  blk.{l}.attn_q.weight[256,256]+attn_q.bias[256]
  blk.{l}.attn_k.weight[256,256]+attn_k.bias[256]
  blk.{l}.attn_v.weight[256,256]+attn_v.bias[256]
  blk.{l}.attn_q_norm.weight ne=[1,2]  (=[1, n_head]; per-head scalar q gain)
  blk.{l}.attn_output.weight[256,256]
  blk.{l}.layer_output_scale.weight[1]  (the per-layer embd-skip out_scale)
  blk.{l}.ffn_gate/up.weight[256,384], ffn_down.weight[384,256]
Globals: token_embd.weight[256,128], output.weight[256,128]. ABSENT (confirming non-param norms): NO attn_norm.weight, NO ffn_norm.weight, NO attn_k_norm.weight, NO token_embd_norm.weight, NO output_norm.weight. Neutral mapping status: attn_q_norm.weight -> self_attn.q_norm.weight (LAYER_MAP :1136, already mapped but shape is [1,n_head] not [head_dim]); layer_output_scale.weight -> layer_scalar (LAYER_MAP :1170, already mapped, and loaded per-layer into Model.ls_dev llm.rs:1433-1441). No new mapping rows needed EXCEPT the qkv bias rows (same gap as lfm2: attn_q/k/v.bias unmapped).
HPARAMS:
{arch}.logit_scale (LLM_KV_LOGIT_SCALE="%s.logit_scale", llama-arch.cpp:207; measured =1.0, so a no-op for this fixture but the mechanism must exist -- models::logit_scale (mod.rs:261) + Spec.logit_scale flag already read hp.logit_scale). {arch}.attention.layer_norm_rms_epsilon (=1e-5). No shortconv/expert keys used (l_cache=0, expert_count=0). Our Hparams already parses logit_scale (llm.rs default 1.0). No new Hparams field required.
HYBRID LAYOUT:
Not hybrid: all layers are attention (head_count_kv=2 for every layer). No interleave metadata. Listed here only because talkie was grouped with the stage-6 skip set; it has no recurrent/shortconv layers.
RISK:
1) Norm placement/shape: current talkie Spec .qk() (mod.rs:157) will look up q_norm AND k_norm as head_dim-length gammas and apply them pre-rope; talkie ships only q_norm as [1,n_head] and applies post-rope with non-param k, so parity fails and k_norm lookup errors (norm_of returns Err, common.rs:195). 2) Non-param block/final/embed norms: talkie ships NO attn_norm/ffn_norm/output_norm/token_embd_norm weights, so any driver that demands them (dense Spec pre_norm+pre_ff) will fail load; must run nonparam RMS at all four positions incl. the embed norm (our decode only applies embed_norm when a gamma+beta layernorm is present, llm.rs:127). 3) embd_skip residual: the per-layer add of out_scale*normed_embedding is a talkie-specific residual with no current analogue (Model.ls_dev exists but is currently applied to scale h_out in a gemma3n MoE path, llm.rs:1855, a different use); the skip source is the frozen initial normed embedding, which the decode loop does not currently retain across layers. 4) qkv bias unmapped (shared gap with lfm2). 5) logit_scale=1.0 here so harmless, but must not be dropped for real talkie checkpoints. 6) F32-vs-bf16 load assumption (llm.rs:1225 nbytes=elems*2) applies to this fixture too.

==== SPEC 3: Gated Delta-Net (GDA), canonical — qwen3next
ARCHS: qwen3next (MoE + shared experts). Reference: llama.cpp/src/models/qwen3next.cpp (build_layer_attn_linear :369-536, build_qkvz :288-367, build_norm_gated :197-206, recurrent-mask :17-23) which delegates the recurrence to llm_build_delta_net_base (delta-net-base.cpp). Fixture: datasets/llamacpp-archs-seed42/qwen3next-moe.gguf (ne=256, nl=2, head_count=2, ssm.state_size=128, ssm.time_step_rank=2, ssm.group_count=2, ssm.conv_kernel=4, ssm.inner_size=256, expert_count=2, expert_used_count=1). Ours today: this arch is table-mapped Comp::Recurrent (models/mod.rs:139) -> the STUB layer_recurrent (common.rs:557-612) which does q/k/v+silu(k)+gpu_scan_linear_recurrence and is entirely wrong for delta-net (no conv, no delta rule, no gating, no hybrid). Full replacement required.
MATH:
Per recurrent layer, decode over T tokens (full-batch, one sequence, no cache; state starts at 0). Dims: head_k=head_v=d=ssm.state_size(128); num_k_heads=Hk=ssm.group_count(2); num_v_heads=Hv=ssm.time_step_rank(2); key_dim=Hk*d(256); value_dim=Hv*d(256); conv_dim=2*key_dim+value_dim = d_inner+2*Hk*d (768). PIPELINE: (a) pre-RMSNorm(attn_norm) -> h [T,ne]. (b) qkvz projection: either fused legacy ssm_in [ne,qkvz_dim=2*key_dim+2*value_dim=1024] split to [q(key_dim),k(key_dim),v(value_dim),z(value_dim)] (qwen3next.cpp:311-365), OR optimized wqkv [ne, conv_dim] + wqkv_gate/z [ne, value_dim] (:299-308). (c) beta+alpha: fused ssm_ba [ne,2*Hv] -> b(Hv),a(Hv); beta=sigmoid(b) [T,Hv]; alpha_softplus=softplus(a + ssm_dt.bias[Hv]); g_log = alpha_softplus * ssm_a[Hv]  (ssm_a already = -exp(A_log) from conversion) -> per-head log-decay [T,Hv]. (d) causal depthwise conv1d over the [q|k|v] mixed tensor width conv_dim, kernel ssm_conv1d [d_conv,conv_dim], left zero-pad (d_conv-1), then SiLU; re-split to q_conv(key_dim),k_conv(key_dim),v_conv(value_dim) at column offsets 0,key_dim,2*key_dim (:407-423). (e) q_conv,k_conv per-head unit-L2-normalize x/sqrt(sum(x^2)+eps) over each d-vector (:431-432); if Hk!=Hv repeat-interleave q/k heads to Hv (:440-444). (f) THE GATED DELTA RULE, per head h, per token t in sequence order, state S_h in R^{d x d} indexed S[i,j] (i=key/query axis, j=value/output axis), q pre-scaled by 1/sqrt(d): (1) decay S[i,j]*=exp(g_log[t,h])  [GDA: same scalar for all j]; (2) sk[j]=sum_i S[i,j]*k[i]; (3) delta d[j]=beta[t,h]*(v[j]-sk[j]); (4) rank-1 write S[i,j]+=k[i]*d[j]; (5) read o[j]=sum_i S[i,j]*q[i]. Authoritative trace: delta-net-base.cpp build_delta_net_autoregressive :339-366 (decay s*=exp(g); sk=sum_rows(s*k); d=(v-sk^T)*beta; S+=k⊗d; o=sum_rows(s*q)). (g) output gate (gated RMSNorm): out = RMSNorm(o, ssm_norm[d]) * SiLU(z)  per head_v (build_norm_gated :197-206). (h) ssm_out projection [value_dim,ne] -> add to residual. Then MoE FFN + shared expert.
KERNELS NEEDED:
NEW: (1) gpu_gated_delta_scan — the fused sequential delta-rule scan. No existing primitive covers the matrix-state rank-1 update; gpu_scan_linear_recurrence (reductions.rs:769 / kernels/scan.hip:311) is only scalar diagonal h=a*h+b and is unusable here. Inputs q,k,v [T,Hv*d], g_log[T,Hv], beta[T,Hv]; output o[T,Hv*d]; state scratch [Hv*d*d]. Geometry: grid=(Hv*n_seqs) workgroups, blockDim=d threads (=128); thread j owns state COLUMN S[:,j] as a private length-d register array (d f64 = 128 VGPR-pairs, resident across the whole T loop -> zero global state traffic); per timestep stage k,q,v,g_log,beta for that head into LDS (d doubles each) and do steps 1-5; write o[t] each step. === MAPPING ONTO gpu_scan_linear_recurrence (gpu-core/src/reductions.rs:769; kernel gpu-core/src/kernels/scan.hip:311-329) ===
The existing kernel computes, per column d of width `dim`, over n_steps: h = a[t*dim+d]*h + b[t*dim+d]; states[t*dim+d]=h; h init 0. That is EXACTLY the bare state recurrence of Step 5 IF you set dim = d_inner*d_state and precompute a[t,(c,n)] = exp(dt_sp[t,c]*A[c,n]) and b[t,(c,n)] = B[t,n]*xc[t,c]*dt_sp[t,c]. Then states[t,(c,n)] holds h_{c,n}[t]. So the recurrence STRUCTURE maps 1:1. What gpu_scan_linear_recurrence does NOT do and must be added: (a) softplus(dt) with the <=20 branch, (b) building a=exp(dt*A) and b=B*x*dt with the per-channel A and per-group B broadcast, (c) the read-out contraction y[t,c]=sum_n states[t,(c,n)]*C[t,n], (d) the D skip and z gate. The materialized route costs a,b,states each [T, d_inner*d_state] f64 (=T*65536*8 B ~ 33 MB/array at T=64) per layer — large but full-batch-legal. RECOMMENDED instead: fork scan.hip:311's kernel into a fused `ssm_scan` (one thread per inner channel holding N=d_state registers, folding softplus/exp/B/C/D inline exactly like ssm-scan.cu) so a/b/states are never materialized. gpu_scan_linear_recurrence is the correct skeleton to fork; it is NOT reusable as-is for a correct mamba layer.
