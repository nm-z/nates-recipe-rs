When Nate corrects a behavior, apply the fix to the entire CLASS of that behavior, not just the one instance. He should never have to re-teach the same root pattern dressed up in a different example.

**Why:** In a single session he re-taught the same root — "you privilege your priors / the norm / CYA over my actual intent" — four separate times (normalizing designs, hedging results, drama-framing problems, fake give-up options). Each was the same root surfacing in a new form. Patching only the named instance forces him to spend his time re-correcting variants instead of doing real work — exactly the waste he is furious about.

**How to apply:** On any correction, ask "what is the root class here?" and fix THAT — in memory + CLAUDE.md — so every variant is covered, not just the example he named. Then actually change the behavior: agreement is demonstrated by the next action, never by saying "you're right." Related: [[feedback_trust_user_over_priors]], [[feedback_terse]].
