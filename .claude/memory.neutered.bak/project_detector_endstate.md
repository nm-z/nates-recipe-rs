User-settled DAG (he inverted the pantry/nates-recipe edge himself — nates-recipe depends on pantry, NOT the reverse):

```
gpu-core                          HIP kernels, links ROCm, depends on nothing
recipe-infer → gpu-core           forward pass + ogdl load. generic "load a saved model, feed input, get output."
                                    no training loop / backprop / optimizer / TUI. the embedded-edge-inference crate.
pantry       → recipe-infer       owns ALL parsing: loaders (csv/arff/zip/dir) + column-type detection
                                    (predict_kinds, tokenize_column, Kind, embedded detector.ogdl) run through
                                    recipe-infer's forward. parse any format → detect types → export OGDL. no training.
nates-recipe → gpu-core,          Model/Train/Data builder, backward, fit, save/resume, preflight, TUI.
               recipe-infer,        Data delegates load+detect to pantry; eval/predict via recipe-infer.
               pantry
catboost-rs / lightgbm-rs / xgboost-rs   standalone, untouched (workspace-excluded already)
```

**Maps onto existing seams (no new logic, just relocation):**
- The infer/train split already exists in `model.rs` gated by `Scratch.infer` / `forward_only`: inference = `attn_forward_cached` (KV-cache, len-1 backward buffers); training = `attn_forward` (full L×L scores) + `backward_step`.
- **recipe-infer** gets the ENTIRE forward + shared representation: `LayerParams`, `Saved`, `Scaler`, `build_layer_params`, `load_ogdl{,_str}`, `Scratch`, `forward_into`, BOTH `attn_forward` (full-batch, training) AND `attn_forward_cached` (KV-cache, inference), `metric_gpu{,_into}`, `sinusoidal_pe`, `concat_layer`, `collapse_onehot`.
- **Cleaner seam than first assumed (confirmed in Phase 1):** `forward_into` is ONE function with the `sc.infer` branch — it can't be split, so it carries both attn helpers. So recipe-infer owns the *whole* forward (training's full-attn path included); nates-recipe keeps ONLY `backward_step` + `fit` + `eval`. No duplicated forward, no Scratch split needed (Scratch lives in recipe-infer, train references it pub(crate) within nates-recipe → at the crate boundary, re-export it from recipe-infer).
- **Phase 1 DONE** (this session): intra-crate split landed on master working tree — `src/utils/infer.rs` (1692, forward+repr+ogdl), `src/utils/train.rs` (1355, backward+fit+eval), slimmed `src/utils/model.rs` (1566, Train/Model builder + preflight), `lib.rs` wired. Pure-move verified (5 critical fn bodies byte-identical). Builds + tests/examples compile. GPU behavioral tests (metric_gpu_tests) NOT yet run (need free GPU).
- **pantry** absorbs `data.rs` + `dataset.rs` loading/format-dispatch + `detect.rs` inference half. The detector *trainer* (`model()` builder, `SOURCES`/`MARCH`/newchic/stocks labels, `corpus_split`, `instances`, `build_dataset`, `train_detector.rs`) STAYS in nates-recipe (needs `Model::new()` + `Train`); it emits `detector.ogdl` which pantry embeds via `include_str!` and ships.

**recipe-infer boundary = pure tensor function (user decision "A", non-negotiable):** recipe-infer takes tensors in, gives tensors out. It does NOT know what a `Dataset` is, where data came from, or what columns mean. "weights + input matrix → output matrix." The `Dataset → Mat` conversion (`collapse_onehot`, any column/onehot/text semantics) is the SEAM between "understanding data" (nates-recipe/pantry) and "running math" (recipe-infer) — mixing them defeats the split. Consequences for Phase 2:
- Move DOWN to recipe-infer: execution-description enums `Activation`, `LayerSpec`, `Loss`, `Metric`, `LayerKind`; structs `LayerParams`, `Saved`, `Scratch`, `Scaler`; all pure `Model::` associated fns (`upload`, `zscore_*`, `nan_impute_and_apply`, `forward_into`, `attn_forward{,_cached}`, `download_*`, `load_ogdl{,_str}`, `sinusoidal_pe`, `concat_layer`). recipe-infer takes `ndarray::Array2<f64>` directly (not `crate::Mat`).
