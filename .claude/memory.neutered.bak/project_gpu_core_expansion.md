Big GPU-feature expansion of the `gpu-core` crate (June 2026): ~150 kernels/bindings across runtime, linalg, math, reductions/scan, encoding, NN, optimizers, losses, and model-family enablers (graph/sequence/cluster/svm/bayes/forest/catboost/rl).

**Architecture decision that enables "one agent per file":** `extern "C"` FFI blocks can be split across many Rust modules, so each domain gets its own `src/<domain>.rs` (own FFI block + `gpu_*` wrappers) and `src/kernels/<domain>.hip` (own `launch_*`). The 1759-line `kernels.rs` monolith stops growing. Shared-file edits (`build.rs` glob, `lib.rs` `pub mod`, `Cargo.toml`, making `rocblas_handle`/`check_launch`/`safe_i32` `pub(crate)`) are quarantined to a Foundation phase and an Integrate phase — never during parallel fan-out. New modules depend ONLY on existing public `gpu_*` + existing `GpuBuffer` API, never on each other.

**Verification reality:** no GPU enumerated on this box (`rocminfo` shows only the Ryzen CPU) — gfx1101 dGPU not passed through. Bar is **compile + link + FFI-signature-parity**, NOT runtime. `hipcc --offload-arch=gfx1101 -c` cross-compiles without a GPU. `cargo test --release --no-run` link-checks. The novel parallel kernels (Borůvka MST, union-find, SMO QP, selective scan, forward-backward/Viterbi) are UNVALIDATED until GPU runtime — say so, don't claim they work.

**FFI parity is the silent killer:** C linkage matches on symbol name only, never signature. A dropped/transposed param links green and corrupts at runtime — invisible without a GPU. Always check per-slot kind parity between each `.hip` `launch_*` and its Rust FFI decl. See [[reference_rocm_setup]], [[feedback_no_cya_optimizer]].

**Outcome (delivered):** gpu-core now has 263 `launch_*` kernels (was 136) + 318 public `gpu_*` fns (was 179) across 18 domain modules (hip, memory, kernels, linalg, math_ops, reductions, encoding, nn_f32, attention, optimizers, losses, graph, sequence, cluster, svm, bayes, forest, catboost, rl). Verified: gpu-core compiles (zero warnings) + links (`cargo test --release --no-run`) + FFI parity clean (263==263, 0 name/slot mismatches) + 12/12 rocBLAS/rocSOLVER/rocFFT externs match real `/opt/rocm/include` prototypes slot-for-slot + root crate builds green. NOT verified: runtime (no GPU here) — novel parallel kernels (Borůvka MST, union-find, SMO, fwd-bwd/Viterbi, selective scan, bitonic sort, ordered TS) are linked-but-never-run.

**Problem found by runtime testing (build.rs defect, FIXED):** The recursive-glob `build.rs` did `ar rcs libhipkernels.a <current objects>` into a PERSISTENT archive. `ar r` adds/replaces named members but NEVER removes objects whose `.hip` source was deleted/renamed. The original `math_ops` agent had renamed `activations.hip`→`math.hip`, leaving a stale `activations_hip.o` that kept getting archived → bundled into the gpu-core rlib → "duplicate symbol: launch_rsqrt/round_kernel/…" link failures, INTERMITTENT under concurrent builds. Fix: before `ar`, `remove_file(lib_path)` (rebuild archive fresh) AND purge orphan `*_hip.o` in OUT_DIR whose source no longer exists. Lesson: a glob-driven static-archive build MUST rebuild the archive from scratch each run. Also: the GPU **is** live here — gfx1101 RX 7700 XT is rocminfo Agent 2 (Agent 1 is the CPU; don't `grep -m3` and miss it). Test harness: `cargo test -p gpu-core --release --test <name>` (must use `-p gpu-core`, not bare from workspace root).

**Runtime testing on the live GPU (5-agent team) found 7 bugs total, ALL FIXED + verified (168 tests green):** (1) build.rs stale-object [above]; (2) svm gpu_smo_train — kernel sign `score_j=+F` should be `-F` (svm.hip ~159); (3) svm gpu_smo_train — host `grad_diff = -(score_i + score_j)` should be `-(score_i - score_j)` (=F_i-F_j; svm.rs:179) — compounded with #2, both needed; (4) sequence gpu_forward_backward — shared-mem race, missing __syncthreads in forward_step_kernel (rewrote to per-thread register logsumexp); (5) cluster gpu_boruvka_mst — over-merge (UF unioned ALL edges not just selected) + use-after-free of h_best_edge; (6) linalg gpu_svd — rocSOLVER column-major fed row-major buffer w/ lda=m → factorized transpose (fix: gpu_transpose to col-major first, swap U/Vt); (7) linalg gpu_qr — same lda issue + truncated R copy for tall matrices. The 3 failure classes that compile+link+parity CANNOT catch: column-major BLAS fed row-major data, parallel/shared-mem sync, algorithm logic. Lightly tested: hip.rs Stream/Event/pinned/peer wrappers + memory.rs new async methods (thin FFI). Test files live in gpu-core/tests/t_*.rs.
